## 한국어

- **🪟 콘솔 창이 잠깐 떴다 닫히던 문제 수정**: 앱이 6분마다 agy 사용량을 확인할 때 Windows Terminal 창이 잠깐 열렸다 닫혔습니다. agy가 실행될 때마다 백그라운드 자동 업데이트를 확인하면서 새 콘솔을 만들었기 때문입니다. 이제 앱이 띄우는 agy(사용량 조회·팀원 세션)는 자동 업데이트를 하지 않아 창이 뜨지 않습니다. 사용량 조회는 사용자 MCP 서버를 띄우지 않는 별도 설정으로 실행하며, 사용자 agy 설정은 바꾸지 않습니다.
- **⬆️ 앱에서 agy 업데이트**: 자동 업데이트를 끈 대신, CLI 관리 화면의 업데이트 확인 목록에 agy가 함께 나옵니다. 버튼과 안내 문구도 npm 전용 표현을 빼고 'CLI 업데이트 확인'으로 바꿨습니다.
- **📭 메뉴 화면에 배정을 넣고 '전달됨'으로 처리하던 문제 수정**: 팀원 화면이 메뉴·설정·권한 확인 같은 화면에 있을 때 앱이 배정을 써 넣고 전달된 것으로 처리해, 실제로는 받지 못한 작업이 '진행 중'으로 보였습니다. 이제 입력창이 아니면 쓰지 않고 '팀원 화면이 메뉴에 있음'으로 기다리며, 메뉴가 2분 넘게 남아 있으면 Esc를 한 번 눌러 빠져나옵니다.
- **🗂️ 옛 대화 기록을 새 세션 것으로 착각하던 문제 수정**: 며칠 전 대화 기록을 여러 세션에서 계속 골라 써서, 옛 기록에 남은 입력을 새 전달 성공으로 오인할 수 있었습니다. 이제 세션이 시작된 뒤의 기록만 고르고, 다른 세션이 쓰는 기록은 제외합니다. 맞는 기록이 없으면 화면을 보고 판단하므로 전달이 막히지 않습니다. 모든 CLI·모든 프로젝트에 적용됩니다.
- **🔁 쉬는 팀원에게 '이어서 끝까지' 요청**: 팀원이 작업을 끝내지 않고 '진행 중' 메모만 남긴 채 쉬면, 앱이 상태 갱신이 아니라 작업을 이어서 끝까지 하라고 알립니다. 2번 알린 뒤에도 멈추지 않고 5분·15분 간격으로 다시 알리며, 3번째부터는 PM에게도 한 번 알립니다. 작업판 카드에 요청 횟수가 표시됩니다.
- **🔗 릴레이 후 바로 이어서 작업**: 컨텍스트가 차서 새 세션으로 넘어간 팀원이 인계 내용을 읽기만 하고 멈추지 않고, 하던 작업을 바로 이어 갑니다.
- **🔌 터미널을 닫으면 연결 거부·다시 열리지 않던 문제 수정**: Headroom을 쓰는 AI 터미널들은 프록시 하나를 함께 쓰는데, 그 프록시를 띄운 터미널을 닫으면 다른 터미널에서 연결 거부 오류가 나고, 새 터미널은 응답 없이 열리지 않아 앱을 다시 켜야 했습니다. 이제 앱이 프록시를 지켜보다 꺼지면 자동으로 다시 띄우고, 터미널을 닫았다 다시 열어도 앱 재시작 없이 열립니다.
- **⏳ 쉬는 팀원을 '응답 중'으로 보고 전달을 막던 문제 수정**: 대화 기록에 턴 종료가 남지 않으면, 팀원이 빈 입력창에서 쉬고 있어도 '팀원이 응답 중(턴 종료 신호 대기)'으로 배정·메일이 계속 대기했습니다. 이제 기록과 화면이 60초 넘게 멈춰 있고 입력창이 비어 있으면 쉬는 것으로 보고 전달합니다. 화면에 작업 표시가 있으면 끼어들지 않습니다. 모든 CLI에 적용됩니다.

## English

- **🪟 Fixed a console window briefly popping up**: Every six minutes, when the app checked agy usage, a Windows Terminal window flashed open and closed. agy checked for background updates each time it ran, which created a new console. agy instances launched by the app (usage checks and teammate sessions) no longer auto-update, so no window appears. Usage checks run with a separate configuration that doesn't start your MCP servers, and your agy settings are left unchanged.
- **⬆️ Update agy from the app**: With auto-update turned off, agy now appears in the update list on the CLI management screen. The button and messages no longer say npm-only; the button now reads "Check CLI updates".
- **📭 Fixed assignments marked "delivered" while a teammate's screen showed a menu**: When a teammate's screen was on a menu, settings, or permission prompt, the app typed the assignment anyway and marked it delivered, so tasks the teammate never received showed as "In progress". The app now waits with "Teammate screen is on a menu" instead, and presses Esc once if the menu stays open for more than two minutes.
- **🗂️ Fixed old conversation logs mistaken for new sessions**: A conversation log from days earlier kept being picked across sessions, so leftover input in it could be mistaken for a successful new delivery. The app now only picks logs started after the session began and skips logs another session is using. If no log matches, it checks the screen instead, so delivery isn't blocked. This applies to every CLI and every project.
- **🔁 Idle teammates are asked to finish the task**: If a teammate goes idle leaving only an "in progress" note, the app now asks them to continue the task to completion rather than just update the status. After two reminders it keeps reminding at 5- and 15-minute intervals, and from the third reminder it also notifies the PM once. The task card shows how many times it has asked.
- **🔗 Work continues right after a relay**: A teammate moved to a new session after its context filled up now picks up the task immediately instead of stopping after reading the handoff.
- **🔌 Fixed connection-refused errors and terminals that wouldn't reopen**: AI terminals using Headroom share one proxy. Closing the terminal that started it caused connection-refused errors in the others, and new terminals hung without opening until the app was restarted. The app now watches the proxy and restarts it automatically if it stops, and closed terminals reopen without restarting the app.
- **⏳ Fixed idle teammates treated as "responding"**: When a conversation log never recorded the end of a turn, assignments and mail stayed queued as "Teammate is responding (waiting for turn-end signal)" even though the teammate sat idle at an empty prompt. If the log and screen have both been still for over 60 seconds and the prompt is empty, the app now treats the teammate as idle and delivers. It still won't interrupt while the screen shows work in progress. This applies to every CLI.
