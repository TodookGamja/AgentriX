## 한국어
- **🚀 팀 시작 직후 지시 전달 수정**: 1.0.5부터 팀을 시작하면 PM에게 첫 목표가 들어가지 않아 모든 팀원 화면이 비어 있던 문제를 고쳤습니다. 출근 브리핑 턴이 없어진 뒤 '턴 종료 신호'가 생기지 않았던 것이 원인으로, 아직 지시를 받은 적 없는 새 세션은 출력이 멈추면 바로 전달합니다
- **🏷️ 역할 적용 상태 표시**: 터미널 상단에 '역할 적용됨'(시스템 지시로 적용 또는 첫 지시와 함께 전달 완료) / '역할 대기'(첫 지시에 붙여 전달 예정) 배지를 표시하고, 출근 안내 줄에도 전달 방식을 적습니다. 대화 턴은 쓰지 않습니다
- **🧑‍💻 팀 추천에 개발자 필수**: 추천 팀에 코드를 직접 구현하는 개발자가 빠지던 문제를 고쳤습니다. '정석 구성을 피하라'는 지시를 없애고 개발자 1명 이상을 필수로 요구하며, 개발자가 없는 결과가 오면 한 번 다시 요청합니다
- **🔍 프로젝트 분석 확대**: 팀 추천 시 하위 폴더 1단계, 하위 폴더의 설정 파일(예: `src-tauri/Cargo.toml`)까지 최대 6개, 확장자별 파일 수를 함께 분석해 주력 스택을 정확히 파악합니다

### 알려진 제한
- 개발자 재요청은 1회만 합니다. 두 번째 결과에도 개발자가 없으면 그대로 표시되니 다시 추천을 눌러 주세요
- 확장자 통계는 파일 2만 개·깊이 6까지만 셉니다

## English
- **🚀 Instructions delivered right after team start**: Since 1.0.5 the PM never received the first goal after starting a team, leaving every member's terminal empty. Removing the clock-in briefing turn meant no "turn finished" signal ever appeared; fresh sessions that have never received input now get delivery as soon as their output goes quiet
- **🏷️ Role status badge**: The terminal header shows "역할 적용됨" (applied via system instruction, or sent with the first instruction) / "역할 대기" (will be prepended to the first instruction), and the clock-in banner states how the role was delivered. No chat turn is used
- **🧑‍💻 Recommended teams always include a developer**: Removed the "avoid the standard lineup" instruction, require at least one hands-on developer, and retry once if the result has none
- **🔍 Deeper project analysis**: Team recommendation now sees one level of subfolders, up to 6 manifests including nested ones (e.g. `src-tauri/Cargo.toml`), and per-extension file counts to identify the main stack

### Known limitations
- The developer retry happens once; if the second result still lacks one, it is shown as-is — press recommend again
- Extension stats count up to 20,000 files and depth 6
