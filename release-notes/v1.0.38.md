## 한국어

- **📬 이미 받은 배정이 '대기'에 남던 문제 수정**: 팀원이 작업표를 보고 배정을 먼저 시작했는데도 앱 대기열에 같은 배정이 남아 작업판에 '대기'로 보이고, 턴이 끝나면 같은 배정이 한 번 더 들어가던 문제를 고쳤습니다. 담당 팀원이 보낸 메일 제목이나 본문에 그 작업 ID가 있으면 대기열의 같은 배정을 닫고 작업판에 '진행 중'으로 표시합니다. 다른 팀원의 항목이나 다른 작업은 그대로 둡니다.
- **💤 쉬고 있는 팀원을 '응답 중'으로 오판하던 문제 수정**: 팀원의 대화 기록을 찾지 못하면 화면에서 입력을 기다리고 있어도 '팀원이 응답 중'으로 계속 막히던 문제를 고쳤습니다. 이제 기록을 찾지 못하면 화면을 보고 판단합니다. 입력을 기다리고 있으면 전달하고, 작업 중이면 지금처럼 기다립니다. 이전 대화를 이어 연 세션의 기록을 빠뜨리던 경로도 고쳤습니다. 모든 프로젝트와 Claude·Codex·agy·Cursor에 적용됩니다.
- **📝 막힘 원인 기록**: 세션 시작 시각과 앱이 고른 대화 기록(없으면 그 사유)을 전달 로그에 남겨, 다시 막히면 원인을 확인할 수 있습니다.
- **⚠️ 알려진 제약**: Grok·OpenCode는 작업 중 화면을 확인하지 못해, 기록이 없을 때 앱이 쉬는지 판단하지 않습니다. 대기열에 '유휴 판정 불가 — 지금 보내기 가능'으로 표시되며 직접 보내야 합니다. 이전 버전에서 쉬는 팀원이 막혔던 정확한 원인은 당시 로그가 없어 확정할 수 없습니다.

## English

- **📬 Fixed already-started assignments staying in "Waiting"**: When a teammate picked up an assignment from the task board before the app delivered it, the same assignment stayed in the app's queue, showed as "Waiting" on the board, and was delivered again when the teammate's turn ended. If the assigned teammate's mail mentions the task ID in its subject or body, the queued copy is now closed and the board shows it as "In progress". Other teammates' items and other tasks are left untouched.
- **💤 Fixed idle teammates shown as "responding"**: When the app couldn't find a teammate's conversation log, it kept treating the teammate as "responding" even while the screen was waiting for input. The app now checks the screen in that case: it delivers if the teammate is waiting for input and keeps waiting if it is working. Resumed sessions no longer have their own log skipped. This applies to every project and to Claude, Codex, agy, and Cursor.
- **📝 Blocking cause is now logged**: The delivery log records the session start time and the conversation log the app selected (or why none was found), so future stalls can be traced.
- **⚠️ Known limitation**: Grok and OpenCode working screens couldn't be verified, so when no log is found the app does not guess whether they are idle. The queue shows "Idle state unknown — Send now available" and the item must be sent manually. The exact cause of earlier idle-teammate stalls can't be determined because it wasn't logged.
